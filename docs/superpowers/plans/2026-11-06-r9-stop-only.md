# R9 cooperative stop-only implementation

Goal: deny further R9 launches after an explicit request or uncertain worker outcome, without running R9 or changing old default recipes/gates.

- [x] Test a fresh owned directory control: stop-requested marker, exclusive redacted receipt, sticky stopped state, worker completion/artifact before stop, worker failure/UNKNOWN refuses next launch, root identity replacement refuses.
- [x] Implement private filesystem control and wire only explicit v9 prepare. Check before/after build and layout, corpus case/functional worker boundaries, qualification/calibration/holdout worker boundaries and before candidate/review progression. Old optional-control-absent paths remain byte-semantic equivalent.
- [x] Verify with controlled doubles and intercepted spawn. No actual compiler/Native/collector/root acquisition. Run affected existing tests and architecture checks once at integration; preserve all old gate failures.

A marker named STOP_REQUESTED in the exclusively created executor output requests a cooperative stop. It is not an execution/permission token. Any existence stops; content is never read. The first stop/failure writes r9-stop-receipt.json exclusively and remains sticky. Check owned root identity before receipt IO. A worker wrapper waits for the original operation to preserve/validate/restore its own artifacts before processing a later stop; errors or explicit UNKNOWN cleanup stop subsequent launches. No callback receipt bypasses existing ownership/measurement checks.

No immediate interrupt of synchronous in-flight Cargo/Native/worker/seed preparation, no full process-tree cleanup or hard time/RAM/process isolation is promised. Preparation checks are at case and Node-worker boundaries, not every internal per-file Native bootstrap call. Existing per-request/per-worker timers and fixed154 complete measured slots remain; stopped/incomplete attempts cannot form accepted candidates or numeric approval. Real sampling, values/profile/PACK/publication still separate.
