# P0-W1-001 Common IR Primitives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the Phase 0 schema-first Common IR contract with provider-independent identities, references, source ranges, confidence and resolution, canonical time values, versioned envelopes, typed errors, and deterministic JSON fixtures.

**Architecture:** `@codeatlas/ir` remains the dependency-bottom package and owns Zod schemas plus types inferred from those schemas. Shared JSON fixtures prove valid and invalid boundaries, while explicit parsing helpers convert Zod failures and envelope compatibility failures into stable typed errors. The work is pure and local: it performs no persistence, provider, IPC, source, graph, knowledge, LLM, network, or daemon behavior.

**Tech Stack:** Node.js 24, pnpm 11.19.0, TypeScript 7.0.2 with strict NodeNext ESM, Zod 4.6.1, Node built-in test runner, Prettier 3.9.6, existing architecture dependency checker, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-10-p0-w1-001-common-ir-design.md`

## Global Constraints

- Implement only `P0-W1-001`.
- Keep `@codeatlas/ir` independent from every other `@codeatlas/*` package; its only new runtime dependency is exact `zod@4.6.1`.
- Preserve provider-independent Canonical IR and keep `EntityId` and `CanonicalId` distinct TypeScript brands with an opaque string JSON representation.
- Reject leading/trailing whitespace and whitespace-only IDs without trimming or rewriting identity values.
- Use zero-based, start-inclusive, end-exclusive source coordinates with UTF-8 byte columns.
- Keep `Confidence.score` within inclusive `0..1` and independent from `ResolutionLevel`.
- Public timestamps use exact `YYYY-MM-DDTHH:mm:ss.sssZ`; epoch milliseconds are safe integers used only through explicit conversion helpers.
- Reject unknown object keys, enum values, schema names, and schema versions; do not silently coerce or downgrade.
- Typed errors must not retain complete rejected payloads or secrets.
- Do not implement Source/Revision IR, Code Fact IR, Evidence, storage/migrations, Provider SPI, Native IPC, Java analysis, FactMerger, ExecutionGraph, Knowledge, LLM, embedding, watcher, daemon, or network behavior.
- Do not weaken tests, Fixtures, architecture rules, Quality Gates, or acceptance criteria.
- Completion requires `p0-common-ir-v1`, focused tests, type tests, `pnpm verify`, hosted CI, synchronized Canonical IR/traceability documentation, and fresh evidence in `CURRENT_STATUS.md`.

    super('Schema name does not match the expected Canonical IR contract');

  }
}

export class UnsupportedSchemaVersionError extends IrContractError {
  readonly code = 'UNSUPPORTED_SCHEMA_VERSION' as const;
  constructor(
    readonly schema: string,

    readonly actualVersion: number,

- [ ] **Step 2: Implement recursive JSON validation**

Create `envelope.ts` with Zod's recursive JSON schema so the public type is inferred rather than duplicated:

```ts
export const JsonValueSchema = z.json();
export type JsonValue = z.infer<typeof JsonValueSchema>;

export const SchemaEnvelopeSchema = z.strictObject({
  schema: z.string().trim().min(1),
  version: z.number().int().positive().refine(Number.isSafeInteger),
  payload: JsonValueSchema,
});

type RawSchemaEnvelope = z.infer<typeof SchemaEnvelopeSchema>;
export type SchemaEnvelope<TPayload extends JsonValue = JsonValue> =
  Omit<RawSchemaEnvelope, 'payload'> & Readonly<{ payload: TPayload }>;
```

`SchemaEnvelope` derives its outer fields from `SchemaEnvelopeSchema` and specializes only the caller-supplied payload type. `z.json()` rejects bigint, symbol, function, `undefined`, `NaN`, and infinities before serialization.

- [ ] **Step 3: Implement envelope construction and ordered parsing**

Export:

```ts
export interface SchemaDescriptor<TPayloadSchema extends z.ZodType<JsonValue>> {
  readonly schema: string;
  readonly version: number;
  readonly payload: TPayloadSchema;
}

export function createSchemaEnvelopeSchema<
  const TSchema extends string,
  const TVersion extends number,
  TPayloadSchema extends z.ZodType<JsonValue>,
>(descriptor: SchemaDescriptor<TPayloadSchema> & {
  readonly schema: TSchema;
  readonly version: TVersion;
}): z.ZodType<SchemaEnvelope<z.output<TPayloadSchema>>>;

export function parseSchemaEnvelope<TPayloadSchema extends z.ZodType<JsonValue>>(
  descriptor: SchemaDescriptor<TPayloadSchema>,
  input: unknown,
): SchemaEnvelope<z.output<TPayloadSchema>>;
```

Validate descriptor schema as non-blank and descriptor version as a positive safe integer when creating a parser. `parseSchemaEnvelope` must first validate a strict raw envelope with a JSON-safe payload, then throw `SchemaMismatchError`, then `UnsupportedSchemaVersionError`, then validate the payload. Prefix payload validation issue paths with `payload`. Return a new plain JSON object containing only schema, version, and parsed payload.
