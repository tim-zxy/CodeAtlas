# P0-W9-003 Metric Engine and Eval CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Calculate auditable node, edge, and critical-fact precision/recall from Canonical comparisons and expose a machine-readable `ekp-dev eval <fixture>` developer command.

**Architecture:** Keep pure metric and gate functions in `@codeatlas/evaluation`, consuming the existing comparator and manifest types. A root-only Node developer script discovers exactly one Fixture, loads two Canonical JSON artifacts, builds the report, and owns stdout/stderr/exit codes; production `apps/cli` remains untouched.

**Tech Stack:** TypeScript 7, Node 24 ESM and `node:test`, pnpm 11, existing `@codeatlas/evaluation`/`@codeatlas/ir`; no new third-party dependency.

**Spec:** [P0-W9-003 design](../specs/2026-09-23-p0-w9-003-metric-engine-eval-cli-design.md)

## Global Constraints

- Read `AGENTS.md` and its ordered handoff authorities before modifying product files. Keep frozen Canonical IR, provider independence, SQLite authority, and Phase 0 scope unchanged.
- `ekp-dev eval <fixture>` takes an explicit directory and exactly one `fixture.json`; use `inputs.actual` and `expected.canonical` JSON files. Run it in-repo with `pnpm ekp-dev eval <fixture>`.
- Only six ratio gate names are supported: `nodePrecision`, `nodeRecall`, `edgePrecision`, `edgeRecall`, `criticalFactPrecision`, `criticalFactRecall`. Gate thresholds are finite and in `[0, 1]`.
- A changed pair is one FP and one FN even with two difference classes; a matching pair is one TP. Zero-denominator metric value is `null` with a reason and cannot auto-pass a gate.
- `criticalFacts[].id` is an expected FactKey; `type` is `NODE` or `EDGE`. Only `importance: "CRITICAL"` enters critical counts. Undeclared extras do not enter critical precision.
- Exit 0: complete report and no failed declared gate; exit 1: complete report with failed/not-evaluable gate; exit 2: controlled input error on stderr and no JSON report. Do not regenerate baselines.
- The current Windows worktree has CRLF-only Git status noise (`git -c core.safecrlf=false diff --quiet HEAD` confirms content equality). Preserve unrelated files. The `pnpm` shim may attempt network-dependent dependency repair; first inspect local dependency state, then use the prior documented offline overrides if needed. Never claim a failed/blocked gate passed.

## Review Focus

- An absolute Fixture directory containing spaces must remain one path argument; the CLI process test in Task 3 uses such a directory.
- A manifest artifact that resolves to a directory rather than the required JSON file must fail with exit 2 and no stdout; Task 3 tests this.
- Syntactically valid JSON with the wrong graph shape must fail via comparator validation and no partial report; Task 3 tests this.
- A non-CRITICAL declaration must be validated but excluded, while an undeclared actual extra still lowers the ordinary category precision; Task 1 tests both.
- No declared gates must yield an explicit empty gate set and exit 0 without claiming threshold compliance; Task 3 tests this.

### Task 2: Pure quality-gate evaluator

**Files:** Create `packages/evaluation/src/quality-gates.ts` and `packages/evaluation/test/quality-gates.test.mjs`; modify `packages/evaluation/src/index.ts`.

**Interfaces:** Consumes `MetricResult['metrics']` and `FixtureManifestV1['qualityGates']`. Produces `evaluateQualityGates(metrics, qualityGates, manifestPath): GateResult`, where `gates` is a stable name-ordered array with `name`, `value`, `operator`, `threshold`, `status: 'PASS'|'FAIL'|'NOT_EVALUABLE'`, and `overall: 'PASS'|'FAIL'`; no gates yields `gates: []`, `overall: 'PASS'`. Throws `FixtureRegistryError` at `qualityGates.<name>` or `.threshold` for unsupported names/thresholds.

- [ ] **Step 1: Write failing table tests.** For each of `>=`, `>`, `<=`, `<`, `==`, test a boundary and an off-boundary value. Test a `null` metric becoming `NOT_EVALUABLE` and overall `FAIL`, two gates ordered by ordinal name regardless of insertion order, no gates, unknown gate name, and `-0.01`, `1.01`, `NaN`, `Infinity` thresholds. Example:

  ```js
  const metrics = {
    nodeRecall: { value: null, reason: 'NO_EXPECTED_FACTS' },
    edgePrecision: { value: 0.8, reason: null },
  };
  const result = evaluateQualityGates(metrics, {
    nodeRecall: { operator: '>=', threshold: 0.9 },
    edgePrecision: { operator: '>', threshold: 0.8 },
  }, 'fixture.json');
  assert.deepEqual(result.gates.map((gate) => gate.name), ['edgePrecision', 'nodeRecall']);
  assert.equal(result.overall, 'FAIL');
  ```

- [ ] **Step 3: Implement and export.** Validate every gate before evaluating any, use a closed comparator switch, then map in ordinal key order. Do not round metric values or silently skip unknown keys:

  ```ts
  const allowed = new Set<MetricName>(['nodePrecision', 'nodeRecall', 'edgePrecision', 'edgeRecall', 'criticalFactPrecision', 'criticalFactRecall']);
  const passes = (value: number, operator: QualityGateOperator, threshold: number): boolean => {
    switch (operator) {
      case '>=': return value >= threshold;
      case '>': return value > threshold;
      case '<=': return value <= threshold;
      case '<': return value < threshold;
      case '==': return value === threshold;

  };
  ```
