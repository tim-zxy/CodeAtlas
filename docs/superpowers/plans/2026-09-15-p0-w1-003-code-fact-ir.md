# P0-W1-003 Code Fact IR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement strict Provider and Canonical Code Fact wire contracts that preserve provider-independent identity and unresolved uncertainty without adding normalization, Evidence, storage, or graph activation.

**Architecture:** Extend only dependency-bottom `@codeatlas/ir` with separate Provider and Canonical schemas, separately branded identities and FactKeys, typed node references, and parallel target-resolution unions. Static JSON Fixtures and test-local Common IR descriptors prove runtime validation, compile-time brand separation, JSON round-trips, and version-1 envelope behavior.

**Tech Stack:** TypeScript 7.0.2, Node.js 24, Zod 4.6.1, Node test runner, JSON Fixtures, pnpm 11.19.0, existing Rust and 17-project architecture gates.

**Spec:** `docs/superpowers/specs/2026-09-15-p0-w1-003-code-fact-ir-design.md`

## Global Constraints

- Preserve provider-independent Canonical IR; Provider facts and Canonical facts remain separate strict objects.
- `@codeatlas/ir` imports no other `@codeatlas/*` package.
- SQLite remains the future authoritative store; this task adds no database, migration, transaction, staging, or activation behavior.
- Provider facts use `ProviderId` plus `ProviderFactId`; Canonical facts use `CanonicalId` plus `NodeFactKey` or `EdgeFactKey`. These identities are never substituted for one another.
- `providerSnapshotId` is observation provenance on Provider facts and is not part of `ProviderFactRef` identity.
- FactKeys are accepted as opaque exact values. This task does not compute, hash, normalize, merge, or enforce graph-wide uniqueness for them.
- Edge endpoints accept only Node references. A reference does not prove that its target exists or belongs to the same repository/revision.
- Target resolution preserves `EXACT`, `HEURISTIC`, `AMBIGUOUS`, `UNRESOLVED`, and `UNSUPPORTED` without sorting, deduplicating, selecting, promoting, or inferring a result.
- `AMBIGUOUS` has at least two unique candidates; `UNRESOLVED` has zero or more unique candidates; `UNSUPPORTED` has exactly zero candidates.
- Every Provider and Canonical fact requires `Confidence`; nodes do not carry a resolution field.
- Evidence, support, and ProviderFactBinding belong to P0-W1-004. FactKey generation and normalization belong to P05-W4-001. FactMerger authority/scoring and Confidence aggregation belong to P05-W4-002.
- Do not add arbitrary attributes, Provider payload escape hatches, Provider SPI, Native IPC, parsing, scanning, graph queries, ExecutionGraph, RuntimeFlow, BusinessFlow, Knowledge, LLM, embedding, network, watcher, daemon, or Phase 1+ behavior.
- All public objects are strict, JSON-safe Zod contracts. Required nullable fields must be present with a value or `null`; explicit `undefined` is invalid.
- Failures reuse `IR_VALIDATION_FAILED`, `SCHEMA_MISMATCH`, and `UNSUPPORTED_SCHEMA_VERSION`; messages remain controlled, bounded to 128 characters, and contain no rejected IDs, names, hints, or source text.
- Do not weaken or delete an existing test, Fixture, Quality Gate, architecture check, Canonical boundary, uncertainty representation, or Evidence boundary.
- Fixture metadata is exactly: ID `p0-code-fact-ir-v1`, task `P0-W1-003`, governing spec `docs/handoff/specs/CANONICAL_IR.md`, acceptance `Provider/canonical identity remains separate`.

- [ ] **Step 4: Implement non-resolved invariants without rewriting input**

Create a private factory over a Node-ref schema and identity function. Its strict shape is `{ state: 'UNRESOLVED', resolution, originalHint, candidates }`. In `superRefine`, check AMBIGUOUS minimum two first, UNSUPPORTED exact zero second, then emit `Target candidates must be unique` at every duplicate index in original order:

```ts
function nonResolvedTargetSchema<TRefSchema extends z.ZodType>(
  refSchema: TRefSchema,
  identity: (value: z.output<TRefSchema>) => string,
) {
  return z.strictObject({
    state: z.literal('UNRESOLVED'),
    resolution: UnresolvedTargetResolutionSchema,
    originalHint: UnresolvedTargetHintSchema,
    candidates: z.array(refSchema),
  }).superRefine((value, context) => {
    if (value.resolution === 'AMBIGUOUS' && value.candidates.length < 2) {
      context.addIssue({ code: 'custom', path: ['candidates'], message: 'Ambiguous targets require at least two candidates' });
      return;
    }
    if (value.resolution === 'UNSUPPORTED' && value.candidates.length !== 0) {
      context.addIssue({ code: 'custom', path: ['candidates'], message: 'Unsupported targets cannot contain candidates' });
      return;
    }
    const seen = new Set<string>();
    value.candidates.forEach((candidate, index) => {
      const key = identity(candidate);
      if (seen.has(key)) {
        context.addIssue({ code: 'custom', path: ['candidates', index], message: 'Target candidates must be unique' });
      } else {
        seen.add(key);
      }
    });
  });
}
export const ProviderNonResolvedTargetSchema = nonResolvedTargetSchema(
  ProviderNodeRefSchema,
  ({ providerId, providerFactId }) => `${providerId}\u0000${providerFactId}`,
);
export const CanonicalNonResolvedTargetSchema = nonResolvedTargetSchema(
  CanonicalNodeRefSchema,
  ({ id }) => id,
);
```
