# P05-W4-002 FactMerger v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce one deterministic, validated Canonical current view with independent Evidence and bindings from multiple eligible Provider observations, preserving a fact until its last support disappears.

**Architecture:** Keep the merger pure in `@codeatlas/providers`; separate versioned evidence identity, input/support validation, and fact selection. The public entry composes those units and never writes SQLite or activates a graph. P05-W1-010/011 consume the output and own transactional persistence and historical Evidence transitions.

**Tech Stack:** TypeScript/Node, existing `@codeatlas/ir` Zod schemas, SHA-256 from `node:crypto`, Node test runner, registered Evaluation Fixtures; no new dependency or migration.

**Spec:** `docs/superpowers/specs/2026-09-28-p05-w4-002-fact-merger-design.md`

## Global Constraints

- Work from merge base `917e56965f93ddfd8c3ce3faf5c2898a7878ad51`; P05-W4-001 normalizer output and Canonical key vectors must remain unchanged.
- Use only `SUCCEEDED` ProviderSnapshot observations as active supports; `PARTIAL`, `FAILED`, and `CANCELLED` cannot yield an applicable merged batch.
- Do not change Canonical IR, Evidence IR, Native IPC, ProviderSnapshot, or SQLite schemas; do not implement SQL Apply, REFRESH, routing authority, Knowledge, or new numerical gates.
- Preserve Provider-independent FactKeys, distinct Provider Evidence/Binding rows, honest unresolved targets, minimum-score multi-support Confidence, deterministic ordering, typed atomic errors, and no raw source text in errors/explanations.
- No product-code edits before this plan is reviewed and an execution method is selected. Follow `AGENTS.md` handoff reading order and record fresh Fixture, test, architecture, and status evidence.

## File Structure

- `packages/providers/src/identity-tuple.ts`: exact shared UTF-8 tuple encoding and malformed-Unicode rejection; no Provider or IR policy.
- `packages/providers/src/canonical-fact-identity.ts`: reuse the encoder without changing existing domains or vectors.
- `packages/providers/src/provider-evidence-identity.ts`: derive one opaque Evidence ID from a Provider observation tuple.
- `packages/providers/src/fact-merger-input.ts`: public input types, controlled error, strict context validation, and one support record per normalized pair.
- `packages/providers/src/fact-merger-selection.ts`: group support, choose real representatives, aggregate Confidence, explain conflicts, and verify merged references.
- `packages/providers/src/fact-merger.ts`: public pure orchestration/output; `src/index.ts` exports only the approved entry, types, and error.
- Focused `packages/providers/test/{provider-evidence-identity,fact-merger-input,fact-merger-selection,fact-merger}.test.mjs`; registered `fixtures/normalization/two-provider-same-call/` pins full/removal outputs.
- `package.json`, `scripts/test-workspace-structure.mjs`, and the controlling Handoff docs register tests and evidence. Do not modify pre-existing Fixture goldens.

## Review Focus

1. An unpaired surrogate in an otherwise valid Provider ID must fail before UTF-8 replacement can alias another Evidence ID (Task 1 test).
2. A second snapshot of the same Provider in one active input must be rejected, rather than double-counting stale support (Task 2 test).
3. Two same-key unresolved observations with different candidate sets must not yield their invented union (Task 3 test).
4. A retained edge whose source or resolved target is absent from the merged node set must fail atomically, not produce a dangling graph (Task 3 test).
5. Removing all supports after a valid two-support batch must yield zero current facts, Evidence, and bindings without implying deletion of stored history (Task 4 Fixture test).
