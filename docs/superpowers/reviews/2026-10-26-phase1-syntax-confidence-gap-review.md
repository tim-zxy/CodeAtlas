## 当前结论

H2-R1 的私有 raw → 声明式历史候选衔接已在局部范围完成。开始本轮时，其封存的6454项哈希全部匹配；本轮不重跑988项测试，也不更改其源码、Fixture、产物或证据。R1 的三个原始详细报告丢失限制继续成立，重建件仍是 NOT_ORIGINAL，不能因哈希匹配而宣称原始证据完整。

下一项值得先解决的设计决策是：Syntax 的 confidence.score 究竟表达“固定规则下的证据支持程度”，还是“经过独立测量校准的正确概率”。现行 [证据协议](../specs/2026-10-25-phase1-syntax-confidence-evidence-protocol.md)明确两者尚未选择。推荐先设计前者的非数值契约，说明适用证据、分类和拒绝规则；待证据方案评审后，再分别审查候选分数及其依据。此建议没有选择任何 score、阈值、权重、分档数量或规则标识，也不允许用示例分数解锁实现。

## 实码与契约约束

- [Canonical confidence](../../../packages/ir/src/confidence.ts)要求 score/method/reasons；score 的既有合法范围仅为结构约束，不是 Syntax 取值依据，不能把合法值当默认值。
- [Canonical Syntax](../../../packages/ir/src/syntax-evidence.ts)的五类对象都需要 confidence，引用还必须满足严格上下文校验。不能用 null、删字段、临时 DTO 冒充已完成的 Canonical Syntax。
- [既有映射附约](../specs/2026-10-25-phase1-syntax-mapping-confidence-design.md)已要求固定版本策略、独立证据及明确批准；缺策略时拒绝新 Canonical Syntax。Code owner 的分数、Library 测试通过或摘要匹配均不能代替它。
- [R1 bridge](../../../packages/providers/src/declared-delta-raw-support-candidate.ts)只提供声明式 Code/history candidate 和 immutable raw，保留未认证边界。它没有产生 Syntax 分数、Syntax origin/current projection 或 final Code basis。
- 先前附约中的实码表是当时快照：历史续接缺口现已由 R1 局部补齐；策略、Syntax 映射、最终 basis、Stage/Store/真实运行缺口仍在。

## 两条可行路线

**A（推荐）：先设计固定规则下的证据支持度。** 限于表面 Syntax 与支持来源的一致性，明确不是框架或运行正确率；使用现有 score/method/reasons 形状，先形成非数值的适用/拒绝/证据契约，再确定需要补哪些独立材料。优点是吻合当前 candidate-only 和分层证据协议，能避免为概率解释启动无必要校准。限制是仍需独立依据及单独数值批准，不能仅凭设计给分或宣称解锁 H2/H3。

**B：先设计校准概率的证据方案。** 先定义可验证的正确性事件、独立标注/留出规则、失败和遗漏计入方式以及分层评估，再提出任何测量和校准操作。优点是未来有条件解释为概率；限制是现有材料不具备这一资格，需要更完整证据设计，实际采集/执行仍单独批准。不得为方便把计数或通过率直接转换成置信概率。

不推荐继续增加与策略无关的零散准备组件，或重复同18例历史采集：前者不能解除当前主要阻塞，后者也不会自动补齐缺失分层。若后续证据显示必须做其他前置工作，应由具体依赖说明，而非推测扩范围。
