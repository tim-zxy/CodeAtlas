## Findings and corrections incorporated before handoff

- Existing history accepts arbitrary valid unit ids and requires oldId on reobservation. Recomputing every id would break legacy continuity. Proposal preserves oldId and limits the new formula to new descriptors; independent literal/collision/legacy controls remain required.
- Native supports require exactly one dependency unit. Proposal uses Java group or exact Python Source ownership and refuses ambiguity; it does not introduce a speculative cross-file Python resolver.
- Snapshot capability completeness alone cannot prove per-unit coverage. Proposal separately constructs every required unit's dual coverage, including zero facts, only after admitted complete raw; all untouched coverage stays with existing history rules.
- Calling existing public history/delta wrappers would reset the budget. Proposal requires a fixed same-ledger continuation with all existing observation checks and exact old wrapper parity; no caller Prepared trust or numerical limit inflation.
- R0 metadata contains only a snapshot header. Proposal explicitly constructs/validates one full ProviderSnapshot using existing full rules, without one-snapshot-per-file fiction or calling the full-only reader on partial input.
- Code candidates are not a final authenticated basis or a complete Syntax activation. Output/exit labels preserve this distinction; missing confidence policy continues to block Canonical Syntax.
- ESM import ordering failed in R0 historically. Subsequent plan must include direct module and public-index import-order controls when extracting kernels; no extra abstraction is justified merely to refactor.
- Tuple encoder allocates buffers and returns a domain-prefixed id. Plan must pin exact output bytes and charge encoding before hashing; a domain label is a new governed identity contract, not an accepted old helper policy.
