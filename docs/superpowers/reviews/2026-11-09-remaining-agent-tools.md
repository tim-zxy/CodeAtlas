# Remaining Agent tools: consolidated decision note

Status PROPOSED_NOT_APPROVED, not a new frozen contract or permission. Source inspected at33e6a90; current batch changes only existing three-tool SDK composition.

## Existing authority and reusable implementation

knowledge-and-consumption sections5/9 and AGENT_API already fix six tool names, no implicit update on reads, workspace-owned scope, permission/budget/cancel, distinct SourceFreshness and CompilationCurrency, no remote fallback. Application CodeQueryRequest already has UNDERSTAND and CODE_TRACE with exact CanonicalId/repository/budgets; strict CanonicalNode/Edge schemas contain no raw body or arbitrary properties. Its output retains facts/source/evidence refs and Provider coverage, under persisted-source freshness CURRENT|STALE|UNKNOWN, worktree NOT_OBSERVED. Runtime currently receives a server-side databasePath and opens/closes the code read port; this path must never be a public MCP argument.

Knowledge selected metadata and existing publication/read ports are available in self-owned temporary DBs. SourceFreshness FRESH|AFFECTED|STALE and CompilationCurrency CURRENT|OUTDATED_* are defined. The publication experiment is explicitly OWNED_TEST_PUBLICATION/NOT_EVALUABLE/TEST_REVIEW_NOT_AUTHORITY; its READY/RUNNING/FAILED/COMMITTED attempt state is not CompilationRun's eight frozen states. No real provider-health producer is established by a successful metadata read.

## Recommended single approval package: two read-only v1 slices

1. get_knowledge_status: server-fixed workspace/explicit current published selection, same finite-selection limits as L0, metadata-only (no title/summary/body/FTS). Return exact item/revision/type, stored freshness/currency/coverage, selected/missing/truncated refs and scoped counts only. providerHealth={availability:NOT_OBSERVED,value:null}; compilationRuns={availability:UNAVAILABLE,value:null} until actual safe producers exist, not empty/no activity or HEALTHY. Always EXPLICIT_SELECTION_ONLY/wholeProjectStatus NOT_ASSESSED/productionQuery NOT_AUTHORIZED. A successful status read is not installation/Native qualification. New decisions: precise status envelope/availability/null semantics, selected-only aggregate meaning; existing invariants do not authorize inventing these.

2. understand_symbol: mode STORED_CODE, one server-fixed repository and DB handle, Canonical symbol ID plus exact expected active revision; request version1 and explicit node/edge/metadata-row/full-output byte/token budgets. No path/position/name ambiguity, no code reindex/Source/Native/model. Reuse actual UNDERSTAND result (strict TYPE|SYMBOL node, bounded incoming/outgoing edges, fact/source/evidence refs, original Provider coverage/confidence and persisted-source context). Never parse a returned name as new code or fabricate runtime relevance. entryRuntimeRelevance={availability:NOT_EVALUATED,value:null}. Schema mismatch/revision drift/budget/permission refuse.

The nontrivial public-meta decision: CURRENT from the legacy code reader is not Knowledge FRESH, and UNKNOWN is not STALE. Do not change either Canonical enum or manufacture Phase1 RepoBasis/codeActivationDigest: the old CodeQueryContext does not expose that digest. Recommended first-slice adapter keeps original code freshness/coverage/refs in data.engineeringResult and explicitly uses null/not-applicable for knowledge-specific wrapper metadata, with a fixed explanation. This is a new per-tool public response rule requiring approval; do not silently borrow null semantics from L0's empty/mixed aggregates. Conservative alternative is to withhold understand_symbol until a separate genuine current CodeBasis adapter is available. Exact code output fields reuse existing CodeQueryPayload, not new inferred architecture facts.

Common to both: trusted host ports and existing opaque session pattern, authorization before data materialization and before delivery, fixed exact counter policy covering the complete canonical response, cooperative deadline/cancel and joined close. Only self-owned DB/fixtures; no production principal or user database query. These choices can be approved together; subsequent internal SQL/DTO/SDK implementation details under that contract need no per-tool question. Rollback removes additive advertised routes, preserves history. Risks: client handling of explicit unavailable/null fields; status mistaken for complete workspace health; stored code mistaken for live/runtime proof. Safe alternative: keep tools unadvertised.

## Other remaining scope: do not fake or broaden

update_knowledge cannot be enabled by renaming the offline publication experiment: complete capture/scanning, quality/Evaluation/production publication, permissions and W011 need real admission. No successful update/dry-run alias is fabricated; remain unadvertised. Frozen run states remain CREATED/CAPTURING/GENERATING/VALIDATING/READY/PUBLISHED/FAILED/CANCELLED; INTERRUPTED remains diagnostic, not a ninth status.

CODE trace could later share the same approved code adapter, but current bare CODE selector still returns FEATURE_UNAVAILABLE under the approved BUSINESS contract. Full CODE argument/output branch and incomplete-request compatibility must be explicit; no silent branch replacement. EXECUTION/RUNTIME trace require their actual version/context/support/coverage binding; actual-source evidence/Native gates are not bypassed by a wrapper. L1/L2, complete project overview, search graph/cursors/Chinese ranking and production service remain separate incomplete obligations.
