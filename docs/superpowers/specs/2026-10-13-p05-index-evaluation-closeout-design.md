## Ownership and lifecycle

Application owns input/command policy, discovered-root validation, Source
reconciliation sequencing and full-required outcomes. Factor only the required
shared observation/reconciliation seam from the existing workflow, preserving
stable IDs, complete inventory and failure semantics. Discovered Git root must
equal the validated bound root before replacement. Do not scan twice or silently
register a parent repository when a nested path was supplied.

Storage owns repository initialization/binding/status SQL and implements
Application ports. The initialization transaction creates only repository and
initial state records; all facts, Evidence, bindings, coverage and R010 writes
remain in existing Application/Store publication workflows. Status uses one
consistent read snapshot and validates persisted records.
Private retained/publication readers borrow an already active session snapshot:
they neither issue nested BEGIN nor settle a transaction they do not own.
Locally opened snapshots settle locally; session-owned cleanup stays with the
session. This preserves the same read image through all validation and queries.

Runtime validates operation admission, composes ports, resolves workers and
allowlisted shell-free Native launch, and owns every connection/stage/child.
Apps depend only on the permitted Application/Runtime surface. Do not add
Runtime-to-Source or apps-to-Storage edges. Export only the approved indexing
entry and request/result types, not private preparation or diagnostic bypasses.

On errors/cancellation, retain the last active graph/Evidence/bindings/coverage/
R010/indexed pointer, close TEMP stages and transactions, settle children and
close connections. SourceFreshness may advance independently of graph
activation, as it already does; return the resulting stale/current distinction.
Capture serialization/output failures separately from committed indexing:
an output failure after commit is not rollback and must not encourage an
unqualified blind retry. SIGINT uses the existing client cancellation seam;
this is not an OS-hard real-time interruption guarantee.

One stdout JSON result, controlled stderr diagnostics and documented exit
classes: 0 successful operation/status; 1 operational/admission/analysis failure;
2 invalid input/usage. Reject duplicate flags, unsafe numbers, unknown config
keys and incompatible modes before side effects. Never print raw SQL, source,
unrestricted environment, stderr secrets or native exception stacks.
