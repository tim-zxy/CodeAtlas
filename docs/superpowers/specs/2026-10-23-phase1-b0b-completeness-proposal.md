## 4. 完整性范围

### 4.1 固定输入职责

Application未来从可信完整inventory派生明确投影；投影不是完整仓库。v5每个sourceFiles成员必须有Syntax coverage；其中所有python成员必须有Code coverage，调用方不能通过传一个更小的codeSourceFileIds列表跳过必需Python文件。Java成员只有Syntax责任，其Code由另一个明确的Java v2投影负责。其他语言拒绝，不自动降级/全仓重扫。

targetSource三元组仍是声明；v5结构validator不读取SQLite、不认证完整仓库inventory。真实捕获、未变文件/历史removed的合法性和完整retained+changed合并属于C3-A+B1。未获得这些证据时，完整观察也只是候选。

Java v2全请求能力集合由完整组合设计控制，不能为了成功删掉原必需capability。v5不改变其文件/能力coverage或旧v3全清单guard。

### 4.2 Python固定提取契约 PYTHON_SYNTAX_CODE_V1

这是Native私有、语法关联的最小Code投影名称，不是新增Canonical kind、Python全语言成熟度或全局REFERENCE能力。

| Facet     | 必须枚举的单位                                                                                                                | 不允许的推断                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| MODULE    | 每个请求Python文件恰好一个path-qualified module，包括空文件/仅注释文件                                                        | 空文件不是零module；不凭空创建其他实体                                          |
| FUNCTION  | 支持范围内每个function_definition的声明名/范围/嵌套限定名，包括async；同跨度必须有对应函数owner                               | 不将class变TYPE，不推断调用/继承                                                |
| IMPORT    | 每个import_statement/import_from_statement内明确导入项，保留alias/原hint/范围                                                 | wildcard、不能表示的导入项必须partial/unsupported，不得continue后仍声称覆盖完整 |
| REFERENCE | 当前最小Syntax值投影要求的identifier/attribute引用：assignment RHS及call/decorator参数等被解释为REFERENCE的值，保留不确定目标 | 不称已枚举return表达式/全部标识符/跨文件动态引用，不伪造resolved                |

本契约保持既有最小事实身份和范围。class令FUNCTION facet PARTIAL并记录UNSUPPORTED_CLASS_SCOPE；wildcard导入计入IMPORT的eligible/unsupported单位并记录UNSUPPORTED_WILDCARD_IMPORT。语法错误令所有不能可靠判定的facet PARTIAL并记录SYNTAX_ERROR；缺失声明名/owner、应有import项无法表示同样不能COMPLETE。原因是不能完整满足事前固定的提取义务，而不是把缺失的实体声明为不存在。不会因为class内函数可映射就将class所在文件重新认作完整。非Code的动态值无法静态解释时Syntax PARTIAL；只要Code提取义务独立满足，可以Code COMPLETE，但联合结果仍PARTIAL。

“投影外”的内容必须在这张事前固定表中界定；不能看到遗漏后临时缩小eligible集合。REFERENCE范围与将来的通用代码引用能力不同，UI/能力声明不得混同。新完整性矩阵需要独立Fixture/Evaluation固定；本轮静态分析尚不批准调整旧EVOLVABLE基线。

## 5. 拟议v5 wire与拒绝规则

以下是供评审的具体布局；B0b-1只固定离线契约，不生成生产客户端、descriptor或wire producer。

### 请求

Envelope严格为protocolVersion:5、requestId、sequence:0、type:OBSERVE_CODE_SYNTAX、payload。payload采用v4已有全部字段和类型：
irSchemaVersion、repository、expectedActivationBasis、targetSource、ownerBinding、providerId、providerVersion、providerSnapshotId、extractorVersion、languages、sourceFiles、removedSourceFiles、owners、deadlineEpochMs、resourceBudget；
另必需codeContract:PYTHON_SYNTAX_CODE_V1，无可选回退值、未声明extra key或用户complete/ready字段。

所有旧Source/owner检查在v5重新施加；不放宽旧schema。Java supplied owners与Python已归一化owners的区别保留。预算仍来自有效配置；maxItems按请求累计、maxEvents独立、所有输出metadata也计入事件/字节预算，不能因新增coverage漏记内存/输出。没有猜测新的上限或保留量。

### 事件

所有事件均严格包含protocolVersion:5、requestId、sequence、type、payload。

| type                                | payload                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------- |
| OBSERVATION_STARTED                 | binding                                                                               |
| NODE / EDGE                         | 原ProviderNodeSchema / ProviderEdgeSchema，仅Python契约允许kind                       |
| SYNTAX_OBSERVATION                  | 原NativeSyntaxObservation语义；不得扩大已冻结v4 schema                                |
| CODE_COVERAGE                       | sourceFileId、sourceFingerprint、codeContract、facet、status、limitations、statistics |
| SYNTAX_COVERAGE                     | 原per-file Syntax coverage字段：sourceFileId、sourceFingerprint、status、limitations  |
| DIAGNOSTIC                          | 原ProviderSnapshotDiagnostic                                                          |
| OBSERVATION_COMPLETED               | binding、codeOutcome、syntaxOutcome、outcome、counts、checksum                        |
| OBSERVATION_FAILED / REQUEST_FAILED | 原NativeIpcError语义，固定受控错误消息                                                |

binding精确为expectedActivationBasis、targetSource、ownerBinding、extractorVersion、codeContract、requestChecksum。requestChecksum是唯一原始请求行的UTF-8字节（含最终LF）的SHA256，小写hex；记录端自己计算，consumer从实际发出的原始行复算，不信调用方scalar。它绑定包括removed/limits在内的全部请求字节；不是Source认证、owner-map替代或Store权限。旧owner-map摘要不变。不同编码请求可以有不同校验值，不改变Canonical身份。

CODE_COVERAGE每个Python文件×四facet恰好一项，facet只允许MODULE/FUNCTION/IMPORT/REFERENCE。status COMPLETE/PARTIAL/UNSUPPORTED；limitations为空当且仅当COMPLETE，非完整项必须给受控非空原因。statistics用既有v2分区字段：
eligibleSites、coveredSites、unsupportedSites、partialSites、resolutionCounts{EXACT,HEURISTIC,AMBIGUOUS,UNRESOLVED,UNSUPPORTED}。
分区恒等；MODULE/FUNCTION resolutionCounts全零；IMPORT/REFERENCE各resolution计数之和等于coveredSites。数字来自实际枚举，是数据计数而非新阈值。

COMPLETE要求unsupportedSites/partialSites为零并满足对应输出义务；MODULE eligible/covered恰好一且该file确有一个合法module。FUNCTION covered单位必须有唯一函数fact和对应DECLARATION/owner；IMPORT covered单位必须有对应edge及alias观察；REFERENCE covered单位必须有对应edge和值引用，重复引用按既有输出粒度核对。facet已覆盖但unresolved目标不自动等于事实遗漏；不能将未知目标改为resolved。

consumer能核对已声明单位到输出的对应关系，不能仅凭producer给出的eligibleSites核验Source里没有额外单位。独立oracle仍必要，不增设第二个生产解析器来自证。

counts精确为nodes、edges、syntax、codeCoverage、syntaxCoverage、diagnostics；值均为实际非负安全整数，不允许-0。终端checksum仍是终端之前所有完整原始输出行（含LF）的SHA256，不包括终端自身。连续sequence、request身份、绑定、类型/文件闭包、完整count和末尾唯一terminal全部校验；失败/超限/取消无可适用completed。

确定性顺序沿用已验证的文件path/id标量排序；每file先NODE/EDGE，再SYNTAX_OBSERVATION、四facet固定MODULE/FUNCTION/IMPORT/REFERENCE的CODE_COVERAGE、SYNTAX_COVERAGE、DIAGNOSTIC。没有Code义务的Java不产生CODE_COVERAGE；不得用Java零Code事件冒充Java Code已成功。

### 双结果

codeOutcome只允许COMPLETE/PARTIAL/NOT_APPLICABLE；NOT_APPLICABLE当且仅当本次没有Python文件且没有任何Code coverage/facts。syntaxOutcome只允许COMPLETE/PARTIAL；空文件集合可为COMPLETE，但仅表示空观察范围。UNSUPPORTED facet/file使相应outcome PARTIAL。

outcome只允许SUCCEEDED/PARTIAL。SUCCEEDED当且仅当Syntax COMPLETE且Code COMPLETE或NOT_APPLICABLE；其余PARTIAL。Java-only SUCCEEDED仅说明v5的Java Syntax责任完整，不能作为全组合的Code成功。缺任何Code/Syntax coverage是协议无效，而不是允许通过的PARTIAL。

### B0b-1 可独立落地的纯接口范围

未来最小文件边界为packages/providers/src/native-code-syntax-ipc.ts及独立测试/Fixture，不修改旧native-syntax-ipc.ts。不新增通用proof framework。

拟议纯接口：
validateCodeSyntaxObservationStream(requestBytes:Uint8Array,outputBytes:Uint8Array):ValidatedCodeSyntaxObservation。
requestBytes必须是一条带LF的原始请求，outputBytes为有界原始行流；逐一执行本文件严格shape、plain data/Unicode、绑定、预算、顺序、统计、owner/引用/完整性结构规则。结果递归冻结，精确包含request、events、codeOutcome、syntaxOutcome、outcome、counts、checksum和requestChecksum；不返回captured/ready/publish/token/qualified等授权字段，不读Source/DB或启动进程。各字段来自已验证请求/终端，不合成更强结论。
