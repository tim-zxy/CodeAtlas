# Phase1 H2-S0 declared observation scope design

Date: 2026-10-26. Status: PROPOSED / DESIGN_REVIEW_PENDING, not implementation authority. No product, Fixture, test, build, DB, Native or cloud change in this design turn.

## Recommendation and alternatives

Advance the next **Source observation scope preparation** component before numerical confidence work. It identifies the Source units a later observation would have to cover, using the same H0 history rules before any new observation exists. It does not normalize Syntax, construct an owner handle, authenticate a Stage or enable a run. This follows the explicitly separable H2 raw/scope/owner components in the [accepted mapping annex](2026-10-25-phase1-syntax-mapping-confidence-design.md), while limiting this first slice to scope only.

Alternatives considered:

- **Recommended: share H0's existing scope calculation and expose a private declared pre-observation result.** Minimal product progress without numerical assumptions, another capture or a second diff algorithm. Requires a subsequent exact implementation package and approval.
- **Choose scores or recapture the same corpus first.** R-01's absent strata and non-qualification make this insufficient without separately approved semantics/evidence. Repeating existing captures does not create ARTIFACT or new target-resolution cases.
- **Build full H2/H3/Stage now.** Rejected: no approved numerical policy; final Canonical Syntax, actual owner/lease authenticity and Store/Stage integration remain blocked. A declared scope cannot replace them.

Its observation can be null.

It then checks exact observation coverage and constructs the transition. With required observations and observation=null it intentionally refuses; it is not a pre-request scope API.

## Proposed responsibility and private interface

Keep the first slice entirely in Providers. Prefer the existing history-transition.ts module; no new public package export, plugin interface, generic planner framework or external dependency. Extract the already-existing pre-observation calculation into one private kernel in the same module, then have both the existing draft entry and a new private-module entry use it. No copied competing Source-diff implementation.

Proposed module-only entry (names are part of this proposal, not current API):

```ts
prepareDeclaredNativeObservationScope(input: unknown, limits: unknown): {
  packet: HistoryTransitionPacket;
  limits: HistoryTransitionLimits;
  budget: CompositionBudget;
  scope: Readonly<{
    kind: 'DECLARED_NATIVE_OBSERVATION_SCOPE';
    mode: 'NO_OP' | 'NO_OBSERVATION' | 'OBSERVATION_REQUIRED';
    targetSource: HistoryTransitionPacket['target']['source'];
    diff: HistoryTransitionDraft['diff'];
    requiredUnits: readonly {
      kind: 'JAVA_GROUP' | 'PYTHON_FILE';
      sourceFileIds: readonly string[];
      previousUnitId: string | null;
    }[];
    removedSourceFileIds: readonly string[];
    provenance: {
      kind: 'DECLARED_INPUT';
      historyActivationId: string;
    };
  }>;
}
```

Input remains the strict existing HistoryTransitionPacket with `observation:null`; a non-null observation is invalid for this preparer. Do not accept a new caller-supplied scope, required-unit array, ownership flag, Stage digest or callback. The caller cannot declare what changed. No new contract/policy value is invented by accepting the existing target contract identities as declarations.

The prepared result is internal state for future same-composition use; budget remains the single mutable ledger and is not a serializable receipt or authority. The packet/limits/scope are owned and frozen by established patterns. No package index export or Runtime caller is added in this slice. A future caller must still supply genuine captured context through the governed Storage/Stage path; serialized, cloned or matching DTOs never authenticate it.

The private kernel returns only the existing context needed downstream (diff, required-unit descriptors, unchanged flag and currently reused maps/unitChanged closure). Keep those implementation details private. It adds no selector, identity algorithm, domain hash or new numerical limit. The existing draft's observation validation/support decisions/digests stay in their current path.

## Exact behavior

| Input condition | Proposed result / preserved rule |
| --- | --- |
| Exact unchanged complete state/contracts/content identity | NO_OP, no required units. Still a declared candidate; Runtime must recheck before returning the old activation. |
| Changed/added projected Python file | OBSERVATION_REQUIRED, one PYTHON_FILE descriptor per required file under existing H0 ordering. |
| Any Java group change with surviving Java files | OBSERVATION_REQUIRED, entire target Java group; never changed-only Java. |
| Deletion with no surviving unit needing observation | NO_OBSERVATION under the same current H0 null-observation eligibility; removed IDs remain explicit. No new history/Stage is created here. |
| Mixed changes | Union computed by existing H0 rules; OTHER files stay in full target inventory, independent of whether they generate facts. |
| OTHER-only addition/modification without a qualifying removal | Preserve FULL_ANALYSIS_REQUIRED. Do not generalize “zero facts” into permission to accept observation=null. |
| Changed third-party support/unit or contract requiring revalidation | Preserve OTHER_PROVIDER_REVALIDATION_REQUIRED; do not drop non-winner or non-native support. |
| Missing/stale history, revision/locator/classification/path-identity conflict | Preserve existing HISTORY_UNAVAILABLE/HISTORY_CHANGED/FULL_ANALYSIS_REQUIRED/INVALID_HISTORY behavior as applicable. |
| Non-null observation or caller-supplied scope/authority fields | Reject through existing strict-input/error categories; no new public error code. |

Required-unit descriptors preserve existing JAVA_GROUP-first/Python sorted iteration and existing comparison functions. previousUnitId refers only to a matching old declaration, may be null, and is not a newly allocated unit ID, owner map or authorization token. Removed Source IDs use existing deterministic ordering and no provider identity inference.

The existing `prepareHistoryTransitionDraft` continues to require real declared observation content when requiredUnits is nonempty. Its old full/delta fixtures, canonical bytes/digests, support decisions and errors must remain exact. The new entry makes requirements inspectable before observation; it does not let an incomplete packet pass as a transition.

## Budget, errors, security and recovery

Parse/copy through prepareHistoryTransition once, pass its existing limits and single budget into the shared kernel and downstream work. Preserve the old entry's existing charges/order; do not make old fixtures pass by resetting or raising a budget. New scope output and its required/removed descriptors must be charged to the same ledger before retention. Test aliasing/caller mutation, deep/oversized input and budget exhaustion using existing approved test limits; no default/resource/profile values are introduced.

Reuse HistoryTransitionError categories. Reject atomically with safe codes; never echo Source literals or sensitive paths. No filesystem read, raw expression evaluation, DB, subprocess, network or LLM is permitted in the product function. The complete declared Source inventory is data, not evidence that current disk bytes still match or that permissions/TOCTOU/run qualification passed.

No SQL, R011 schema, canonical model, migration, profile/catalog, old full API, owner-stage body, lease or Store behavior changes. Failure returns no scope and mutates no history/Source/Code/Syntax/pointer. Existing handles, final basis, raw binding and Syntax mapping/confidence remain the responsibility of subsequent separately approved H2/H3–H5 work.
