# Standard locked Wiki profile v1 (owned-data implementation)

Authority: ADR-013, wiki-projection, knowledge-and-consumption section8 and the explicitly adopted EVOLVABLE first-profile refinement. The published-only boundary, no canonical writer/update/model, LOCKED policy and Phase2/3 exclusions remain unchanged. This batch implements only private owned-data ports and in-memory artifacts, no production query/file publication or user DB.

Profile codeatlas.standard@1.0.0 / spec codeatlas.standard-wiki@1 / engine1 / renderer1 has seven ordered sections. Overview and provenance/coverage/freshness are required: at least one fully associated selected published record is necessary; absent records give MISSING_DATA for both. Components, Capabilities, Integrations/Contracts, RuntimeFlow references and BusinessFlow are optional and select their existing five Knowledge types. Missing optional sections are explicit PARTIAL diagnostics. Architecture/Migration is an explicit Phase1 not-applicable note, never invented data. No user profile/options/selector/renderer extensions.

Retain every diagnostic; dominant order REVIEW_REQUIRED > MISSING_DATA > STALE > PARTIAL > COMPLETE. Original unsupported coverage is missing supporting data, partial coverage produces PARTIAL, stored AFFECTED/STALE fails this profile's fresh condition as STALE, and noncurrent compilation policy requires review. These are projection statuses, not canonical state changes or real quality evidence. Only COMPLETE, or PARTIAL with explicit allowPartial=true, may replace the owned current artifact. Required gaps/review/stale cannot be converted to partial permission. Hard invalid policy/selection/IR/reference/scope/control errors refuse, with no artifact change.

The Application instance fixes an owned KnowledgeQuery callback at construction, requests an explicit exact unique revision set under workspace/repository scope, and validates returned selection/envelopes/reference metadata/coverage/provenance before rendering. No direct SQLite reader, graph expansion, source bytes or query-derived authority. Empty selection reports required missing data. Records outside scope, missing/substituted/duplicate members and broken provenance refuse as a whole. Selected historical revisions remain exact; stored/current-head metadata is not a live observation. All results retain OWNED_TEST/NOT_EVALUABLE/NOT_AUTHORIZED labels and LIVE_SOURCE_NOT_OBSERVED limitations.

Knowledge owns deterministic fixed-section Markdown and diagnostics, escaping heading text and using safe literal JSON fences. Only authorized selected published content/reference/support metadata appears, no Claim/source body. Input/version tuple, profile/spec/engine/renderer and rendered content determine fingerprint; new artifact ID is assigned only after unchanged detection. Input order cannot create a new revision. Application copy-on-write retains immutable historical memory revisions; failed read/validation/cancellation cannot move current. This is not the real atomic filesystem artifact writer, durable recovery or production permission acceptance.

Alternatives: require all seven sections (blocks valid partial repositories), or caller-configured requiredness (violates Phase1 LOCKED). Adopt the explicit approved required/optional table. Compatibility: public schemas, current query routes, canonical records and existing output files remain unchanged; previous owned artifact revisions stay addressable. Rollback disables the private projector and retains histories. Original P1-16/full Wiki and quality gates stay OPEN.
