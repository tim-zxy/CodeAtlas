# P1-03 Syntax observation and Plugin V2 contract detail

Authority: accepted ADR-020, the reviewed foundation/runtime plan P1-03 and the user's continuation request. This completes the already selected contract design; no actual observer, grammar, migration, capability advertisement or profile is added.

## Native contract

OBSERVE_SYNTAX selects protocolVersion4 explicitly, sequence0, irSchemaVersion1. Request carries requestId, repository(id/rootPath), RepoBasis, provider identity/snapshot, extractorVersion and language/grammar/compatibility versions, changed sourceFiles, removed file identities, per-file provider-to-canonical owner mappings and explicit deadline/resource budgets. IDs/paths are unique; changed/removed sets are disjoint; owners belong to changed Java files, matching repository/revision/SourceFile and provider identity. Python owners instead bind emitted Python ProviderNode records from this stream. Each selected file is authorized non-secret text SOURCE/TEST Java/Python; arbitrary artifacts use Runtime Source policy in a later task, not filesystem access granted here.

Budget fields: maxDurationMs/maxMemoryBytes/maxEvents/maxInputBytes/maxOutputBytes/maxDepth, all explicit positive safe integers. Existing hard caps remain stdin/line1000000, stdout10000000, events10000; no new default, timing or memory profile number. Bounded raw JSONL validation precedes exposing any result; schema input helpers accept plain JSON only. The stream validator takes raw complete line byte arrays, verifies strict UTF-8/LF, one record per line, request/sequence/version, event legality, per-file identity, reference closure, exactly one terminal and its SHA256 over all pre-terminal bytes including LF. It is not a live process transport.

Events: SYNTAX_STARTED binds basis/extractorVersion; NODE/EDGE use old strict Provider shapes for Python minimal MODULE/SYMBOL and IMPORT/REFERENCE only; SYNTAX_OBSERVATION is provider-owned raw syntax; COVERAGE appears exactly once per changed file; DIAGNOSTIC is file-bounded; SYNTAX_COMPLETED binds basis/extractorVersion/counts/outcome/checksum. Failed terminals refuse the entire result without applicable partial output. SUCCEEDED requires all COMPLETE coverage, otherwise honest PARTIAL. Removed files emit no observations. Every raw owner/reference binds an explicit Java mapping or earlier emitted Python node; no Canonical or framework output is invented by Native.

Raw syntax has providerSyntaxId/sourceFileId/sourceFingerprint/sourceRange/owner and DECORATION/INVOCATION/DECLARATION/ASSIGNMENT/ARTIFACT discriminated payloads. Values are scalar/NULL/ARRAY/OBJECT/UNKNOWN or provider-reference targets using existing ProviderTarget semantics. This mirrors the language-neutral typed syntax vocabulary without inserting Canonical refs into Native facts. Normalization and syntax-key generation remain later tasks. Fixed controlled error codes reuse Native errors. Real DESCRIBE still advertises only evaluated versions/capabilities.

## Plugin V2

Explicit contextVersion2 descriptor uses existing trusted descriptor fields plus contextVersion. Context holds basis, nodes/edges/sourceFiles, normalized syntaxEvidence, supportInventory and JSON configuration. Combined nodes+edges+syntax length shares the unchanged10000 fact cap; files share the10000 file cap. Duplicate facts/keys/files, dangling code endpoints, foreign basis, missing/foreign source/owner and fingerprint mismatch refuse the whole context. References used to validate normalized SyntaxEvidence are derived from the supplied canonical nodes/edges/files, not a separate unbounded caller inventory. Inventory supports bind the same basis and local entity set, with at most one captured value per entity (therefore bounded by that local entity inventory); Storage/Application still authenticate their value digests.

Support is an explicit CANONICAL(ref:CanonicalFactRef) or SYNTAX(id) union, unique and present in context. V2 detection is evidence-backed with support iff matched. Extraction additionally requires positive validated detection. Candidates require a declared semantic capability, strict versioned envelope and nonempty valid support; Application subsequently validates the concrete Runtime/Contract schema and activation basis. Inputs and outputs are validated JSON and deeply frozen; no environment/network/shell/Store port. V1 shapes and dispatch remain unchanged, and passing V2 to V1 fails rather than upgrading it.
