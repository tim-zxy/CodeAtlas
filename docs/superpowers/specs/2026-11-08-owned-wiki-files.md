# Owned Wiki artifact files, private experiment

Existing knowledge-and-consumption section8 already requires exclusive temporary writes, immutable artifact files and atomic current-manifest replacement, preserving old versions on failure. Implement that lifecycle only for newly created self-owned OS temporary directories. Never accept a user outputTarget, install directories, user database or production publication. Standard-library filesystem only, no dependency, migration or public route.

createOwnedWikiArtifactDirectory(control) exclusively creates a fresh codeatlas-owned-wiki-* directory beneath canonical OS tmpdir and writes an immutable owner receipt. It returns {directory,ownerId}; it never adopts an arbitrary existing target. OwnedWikiArtifactFiles(receipt,maxArtifactBytes) can reopen exactly that owned directory with explicit byte allowance, original owner marker and stable ancestor identities. Files are only fixed marker/current/lock names and SHA256-derived revision filenames, no input path segments. lstat/fstat/link-count and ancestor identity checks reject observed symlinks/junctions, hardlinks, replaced/missing nodes and unknown owners. These observed checks are not a secure production deployment or adversarial path-stability proof; production stays closed.

commit(artifact,expectedCurrentRevisionId,control) accepts only labeled owned Wiki artifacts, not production authority; Application remains responsible for actual validated projection. Acquire exclusive lock, read/validate current under the same owner, check CAS and same artifact identity; no overwrite of immutable revision. Serialize once under request controls and explicit byte limit. Write wx temporary file, fsync/close/readback verify, install immutable revision, then write/sync/check a temporary current manifest and atomically rename current. Same current bytes are UNCHANGED; changed bytes for the same revision ID refuse. Complete commit is distinct from postcommit cleanup. Any uncertain pointer outcome blocks further writes on the instance; inspection reads original artifacts, never retries or rewrites automatically. Lock/unknown files are not blindly removed.

readCurrent(control) and readRevision(id,control) bounded-read and validate bytes/hash/owner/identity before returning deeply frozen owned artifacts. Old revisions remain readable after a changed current and after process reopen. No manifest or source text authorizes query, scanning, quality or publication. Writer never initiates query/update/model. Creation and changes use only test-owned data; tests do not claim power-loss durability, hostile-process exclusion or production safety.

Success: real owned projector artifact persists and reopens; unchanged/CAS/conflicting revision/byte limits/cancel/foreign marker/link refusal preserve old current/history; actual rename failure or acknowledgement loss reports UNKNOWN and does not rerun. Use existing guards/patterns where architecture permits; single writer and no arbitrary output paths are mandatory. If production path protection needs a new contract, stop that path and report rather than claiming these experimental guards qualify it.

## Confirmation and reopen boundary

rename(current) returning normally confirms COMMITTED immediately; later cancellation, readback or cleanup failure preserves that effect with cleanup UNKNOWN and blocks the original instance. rename itself throwing, including after the actual rename with lost acknowledgement, leaves publicationEffect UNKNOWN and a persistent pending attempt. Reopened readers can inspect but cannot write while pending/lock evidence remains. A reopened directory with a current revision requires explicit readCurrent before commit; only verified current/hash plus absence of pending/lock permits a new operation. This confirms actual filesystem state, not an automatic rewrite or original-owner resurrection. The old UNKNOWN instance remains blocked even after inspection. If final lock unlink actually completed but lost its receipt, a new read-only inspection can confirm that absence; the same artifact returns UNCHANGED without rewriting. No tombstone/recovery service, user-data access or security permission is introduced.
