# Owned read-service lifecycle, existing P1-18 contract

This implements existing knowledge-and-consumption §9 / RUNTIME_CONFIGURATION / P1-18 startup reconciliation, live-session watcher coordination and joined shutdown. It is an internal owned-data component, not a new production authority, source freshness definition, public tool schema or daemon. Ordinary CLI remains closed; no real project watcher/Source/Git/Native, model, user DB, scan, migration, publication, dependencies or physical resource values.

Reuse current official SDK and nine genuine readonly leaves. Add a private Runtime coordinator and an additive managed-host factory; do not replace existing factories. Constructor captures one workspace/repository set and explicit maxItems/maxDepth/requestTimeoutMs before binding callbacks. Host-supplied reconcile and mode-specific observer callbacks are trusted implementation ports, never request authority. They receive immutable captured scope and fresh per-operation controls with the same owned abort signal. No update/model/index port exists. Coordinator readiness means only its callback completed, not that real Source was observed or any grant was issued.

Start performs STARTUP reconciliation before opening a watcher. MCP_STDIO requires an explicit observer callback; POST_ATTACH reconciliation closes the startup/attach gap; events during acquisition/reconciliation are retained. ONE_SHOT is the no-watcher mode and still performs startup reconciliation. Events are only CHANGE/OVERFLOW, not paths; coalesce to dirty boolean plus highest-priority reason, serialize passes with no overlapping reconciliation and no unbounded path queue. Overflow immediately marks uncertainty. A new event during a pass requires another pass; failure stops service, no automatic retry-to-green.

Increment a bounded-safe monotonic generation on every accepted event, including coalesced events. Managed SDK starts only after initial reconciliation settles. Before dispatch and after each async tool execution, require lifecycle READY and the same generation. Thus a missed-change signal cannot be hidden by a fast reconciliation before delivery. Refuse with the existing typed CONTEXT_UNAVAILABLE, not successful empty data, during uncertainty/generation change. Existing per-request exact revision/basis/permission checks remain necessary; watcher/coordinator readiness cannot replace them.

Close invalidates/aborts immediately, stops protocol and all leaf contexts, joins startup, watcher acquisition, in-flight reconciliation, source queries and writes, then closes any late-acquired observer exactly once. Failed cleanup remains UNKNOWN. Completion is process-local; there is no persisted owner resurrection/recovery or automatic service restart. Unknown callbacks that ignore cancellation keep close pending instead of reporting false settlement. Reentrant start/close must not deadlock. Safe diagnostic state is internal, not global health or source freshness.

Verification uses controlled observer doubles and real self-owned Runtime Store metadata reads plus official child stdio, not a real filesystem watcher or real missed-change qualification. Check startup order/gap, event coalescing+generation, overflow during query before delivery, ONE_SHOT, closure during pending startup/observer/reconcile, callback failure/UNKNOWN, unchanged old factories. Formal P1-18/E14 and Phase1 remain open; no production coverage claim.
