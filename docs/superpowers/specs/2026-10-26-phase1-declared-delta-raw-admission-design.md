## Approaches

**Recommended: one private declared delta admission path, with a budget-aware internal raw validation path.** Reuse strict request/event schemas, checksums and correspondence checks. Keep old public wrappers and full-only scope behavior exact. Couple budget propagation and raw/scope admission in one package because proving them separately would not prove the composition boundary.

Relaxing the old full-only reader or rewriting metadata inventory as the requested subset is excluded: it would weaken an accepted compatibility gate and conceal OTHER/unchanged Source context. A second independent protocol decoder is also excluded: it would duplicate security-sensitive validation. Building the entire bridge/Stage now is excluded by missing confidence policy and unimplemented owner/lease/run authorization. Within the accepted constraints, the private reuse path is the recommended viable route; it is not yet approved.

## Proposed responsibility and data contract

Names below are proposed internal module names, not current or public APIs. A future plan must fix exact signatures/files and demonstrate old/new parity before execution.

A single module-only entry `prepareDeclaredDeltaRawObservation` receives the existing complete history packet with observation=null, declared component metadata, request/output byte arrays and existing explicit composition limits. It calls S0 internally once. It does not accept a caller-supplied scope, Prepared object, ledger, callback, ownerHandle, lease or authenticated flag. No package index export or Runtime/Storage caller is added.

Only `OBSERVATION_REQUIRED` enters this function. `NO_OP` and `NO_OBSERVATION` stay with existing S0/H0 control paths; extra raw on these paths is rejected rather than used to create a new transition. This is an entry precondition, not a change to removal or NO_OP eligibility.

The internal result retains the owned prepared packet/scope, explicit limits and the same budget, plus immutable validated v5 data, checked Java component data when required, and request/output checksum provenance tagged **DECLARED_INPUT**. Raw copied buffers remain internal and are not exposed as mutable candidate properties. Parsed data cannot alias caller-owned metadata or bytes. No generic continuation API is exported to callers.

No `DeclaredNativeObservation`, normalized Python Code candidate, history unit id, coverage-origin membership, final Code basis or Canonical Syntax is emitted. Later composition must reuse this prepared state internally, not serialize it and claim authority. If no caller can consume the private result without another parse/reset, that later integration remains open; do not claim an end-to-end bridge exit.

## Exact scope binding proposed for approval

- Keep the complete target inventory and all removals in S0 scope. Compute the required request Source set as the union of S0 required Java-group/Python-file descriptors, selecting exact SourceFile values from the complete target inventory. Preserve existing UTF8 path/id request order; preserve S0/history ordering separately. No caller decides changed files.
- v5 sourceFiles must equal that required set exactly, not the entire projected inventory and not a caller-chosen subset. All current request/wire validation remains mandatory, including Source roles, sensitivity, languages, unique ids/paths and owner membership.
- Request targetSource must equal S0 targetSource and expectedActivationBasis must equal the validated old history basis. Provider, snapshot, versions, tool descriptors and enclosing/child timestamps must agree. New snapshot must not reuse an old history snapshot id. Structural checks do not prove those timestamps or metadata describe an actual execution.
- Proposed v5 removedSourceFiles are exactly removed old projected native Java/Python SourceFiles, represented with their existing id/path/previous fingerprint and deterministic existing order. OTHER removals remain in complete scope/manifest but are not invented as grammar input. Deletion-only eligible inputs bypass raw admission. This projection is an explicit new local mapping proposal, not an already accepted wire rule.
- Java metadata is required exactly when S0 requires a surviving Java group; its v2 request contains the complete target Java group. Unchanged Java elsewhere in inventory does not require a new Java observation. Preserve v2 capabilities, terminal, fact identities, complete coverage, sizes and error rules.
- v5 must have SUCCEEDED/COMPLETE Syntax and COMPLETE Python Code when Python files are requested, otherwise NOT_APPLICABLE Code, under existing contracts. PARTIAL, failed, malformed, cancelled or incomplete data cannot be a successful admitted candidate. Do not rewrite or erase retained original failure evidence.
- Require PROVISIONAL_CODE for this delta candidate path. Verify owner-map checksum structurally and Java owners against the original controlled Java node/normalization mapping, preserving typed Provider refs. Do not construct or authenticate a real provisional Stage digest or handle. A self-consistent declared digest can pass structural admission and still has no authority.
- No final-winner inference, no replacing original refs with names, no inferred cross-file target resolution or unsupported-language fallback. Final Code/Syntax retained-reference closure belongs to later composition.

The admitted representation describes only the observed units. It must never be stamped as whole-repository observation coverage. The proposed removal projection and entry/data boundary require this design approval and independent fixtures before implementation.

## Cumulative budget and compatibility

Use existing maxSerializedBytes/maxItems/maxDepth and hard wire caps; add no values or defaults. The raw path continues the budget S0 already spent. Before allocating/retaining representations, account owned byte copies, decoded/request/event views, metadata copies, normalization needed for Java owner checks, scope correspondence and output using existing charge primitives and safe subtraction. No reset, refund, truncation or limit increase at a boundary.

The raw validator needs a narrowly scoped internal prepared path carrying the same ledger. Existing public two-argument v5 and full composition wrappers must retain their old signatures, semantic results, errors and charging behavior. Reuse one correspondence/validation implementation; do not add a caller-selectable lax mode or callback-based validator. The internal path is not an authentication primitive.

**Open implementation proof:** charge points must be specified against every actual owned representation in the exact plan. Charging only the final parsed result after all events have been retained is insufficient to demonstrate early cumulative exhaustion. Request wire budgets cannot be silently rewritten to remaining composition limits because that changes signed/checksummed input. A shared validation-core extraction or fixed internal reader context is acceptable only with exact old wrapper parity and pre-retention exhaustion evidence. If that proof cannot be made without changing frozen contracts, stop and submit a narrower DCP before coding.

Resource checks remain logical accounting. They do not establish RSS, process memory, elapsed-time qualification or permission to measure Native. Java helper/normalizer reuse must be bounded and charged; no full merge or selector is needed merely to admit raw scope.

## Errors, security, storage and recovery

Preserve old public error families. The new private boundary must retain safe existing HistoryTransition/native cause codes and distinguish invalid history/context/scope, incomplete observation, protocol corruption and resource exhaustion; exact wrapper mapping is to be fixed in the reviewed plan, not guessed during implementation. Diagnostics must not echo source literals or sensitive paths.

Reject atomically without mutation of Source, history, raw original evidence, Code, Syntax or activation pointer. No filesystem interpretation of Source metadata, expression execution, DB, process, network, shell or LLM inside the function. No SQL/schema/migration or actual capture/Stage/owner/Store change. Immutable DECLARED_INPUT results never confer apply/run rights, even with matching DTOs/digests.

Preserve provider-independent IR, SQLite authority, candidate-only LLM output, AUTO/MANUAL publication and ExecutionGraph -> RuntimeFlow -> BusinessFlow. No DEFERRED capability or new framework enters this component.
