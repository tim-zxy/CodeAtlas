## Exact derived summary contract

All objects are strict; every field below is required and nullable only where stated. New counters/spans are safe and nonnegative (reject negative zero); the reused EpochMilliseconds deadline retains its signed safe-integer contract; spans use zero-based UTF-8 byte columns and start-inclusive/end-exclusive positions with end ≥ start. Reuse SourceFile and ProviderSnapshotDiagnostic schemas, and NativeCapabilityCoverageV2 statistics/equations. IDs, kinds, names and qualified names reuse their matching IR scalars; compatibility/version strings reuse NativeAnalyzerLanguage's exact nonblank ≤128-character scalar. Digests are lowercase SHA-256 hex, exactly 64 characters, not SourceFile fingerprints.

`NativeFileAnalysisSummaryV1`:

| Field         | Type / constraints                                                                                                                                                                                          |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| schemaVersion | literal 1                                                                                                                                                                                                   |
| sourceFile    | existing strict SourceFile                                                                                                                                                                                  |
| symbols       | array of strict `{providerFactId, providerKind, name, qualifiedName: string or null, signature: string, isStatic: boolean, span}`; span has startLine/startColumn/endLine/endColumn; signature may be empty |
| relationSites | array of strict `{kind, variant, sourceFactId, targetHint, arity: safe integer or null, span}`; kind is IMPORT/CALL/INHERITANCE/REFERENCE; variant and targetHint are nonempty strings                      |
| diagnostics   | array of existing ProviderSnapshotDiagnostic                                                                                                                                                                |
| coverage      | array of NativeCapabilityCoverageV2; each sourceFileId equals this source ID; exactly one per requested capability in the enclosing bundle                                                                  |
| emittedFacts  | array of strict `{factType: NODE or EDGE, providerFactId, contentDigest, ownership: FILE or SHARED}`                                                                                                        |

Duplicate symbol IDs or `(factType,providerFactId)` within a summary fail. Every site sourceFactId must identify a symbol in this file or the deterministic compilation-unit ID for this path; shared containers are not an arbitrary source escape hatch. Diagnostic source ranges, when present, reference this file. Preserve honest unresolved sites; do not persist a chosen target in relationSites. signatures/static/import variants are provider-specific cache input, not Canonical fields. Summary strings are bounded by line/aggregate/resource budgets, not a newly invented accuracy threshold.

`NativeAnalysisStateHeaderV1` has exactly:

`schemaVersion:1`, `repositoryId`, `revisionId`, `contentFingerprint`, `providerId`, `providerVersion`, `language` (existing NativeAnalyzerLanguage shape), `resolverVersion`, `normalizerVersion`, `policyFingerprint` (existing ContentFingerprint), `requestedCapabilities` (nonempty unique exact strings), `sourceFileCount` (safe nonnegative integer), `summaryDigest` (64 lowercase hex).

`NativeAnalysisStateBundleV1` is exactly `{header, summaries}`. summary files match header repository/revision and are unique by ID and path; count matches sourceFileCount. Coverage capability set equals the header set. A SHARED fact may occur in multiple files only with identical type/ID/digest and SHARED ownership; any FILE owner is unique across the bundle. All symbol/source relationships and path-derived compilation-unit IDs are verified in both languages. No arbitrary JSON extension bag.

This Java-first packet requires header/context languageId `java`; another language is unsupported input for this packet, not a future capability implicitly registered by a generic metadata shape. SYMBOL/IMPORT/CALL/INHERITANCE/REFERENCE are the current eligible capability names. Every contract string must contain valid Unicode scalar values, including signatures/hints; reuse of an existing string scalar does not waive this cross-language condition. Empty signatures are valid.

Canonical digest recipe `native-state-v1`: reject unpaired UTF-16 surrogates in TypeScript strings (Rust strings already contain Unicode scalar values). Recursively sort object keys by Unicode scalar value, explicitly rather than localeCompare or UTF-16 ordering. Encode compact JSON UTF-8 with no LF and preserve strings without normalization. For digest encoding only, replace each finite numeric value with the reserved single-key object `{"$nativeNumber":"<16 lowercase hex digits>"}` containing its IEEE-754 binary64 bits in big-endian order; `1` is `3ff0000000000000`, positive zero is `0000000000000000`, `0.1` is `3fb999999999999a`. Negative zero is invalid. Validated contract objects cannot contain this reserved key. This avoids TS/Rust exponent/float text-format differences without a canonical-JSON dependency; wire/persisted values stay ordinary numbers. Before hashing, sort summaries by canonical repository path, symbols by providerFactId, sites by `(kind, sourceFactId, startLine, startColumn, endLine, endColumn, variant, targetHint, arity)` with null arity before numbers, diagnostics by their canonical digest-encoded JSON bytes, coverage by capability, emittedFacts by `(factType,providerFactId)`. Duplicate identical sites are invalid rather than silently collapsed. Hash the resulting summaries array bytes with SHA-256. Header is checked separately against request context and excluded from this summaryDigest.

Fact contentDigest uses the same canonical-object encoding of the validated ProviderNode/ProviderEdge after removing only providerSnapshotId. Keep repository/revision and all semantic fields; same-WORKTREE restriction still applies. Tests pin a hand-calculated byte vector, not only two calls to the same implementation. Producer/Store packets will validate correspondence between digests and facts before activation; the schema packet alone cannot prove that correspondence.

All textual array sort keys use Unicode scalar ordering too; do not use default JS UTF-16 array ordering for paths/identifiers. For compilation-unit ownership, preserve the existing Rust recipe exactly: `java-compilation-unit-v1:` plus SHA-256 of UTF-8 bytes `java-compilation-unit-v1\0` + decimal UTF-8 byte length of path + `:` + path. The length is bytes, not JavaScript string.length. Include a non-ASCII path vector.

## v3 request records

One process receives one JSONL request stream. Every record is strict `{protocolVersion:3, requestId, sequence, type, payload}`. requestId follows existing exact ≤128-character rules; sequence starts at zero and is contiguous. No BOM, CR, blank record, malformed UTF-8, trailing partial line or bytes after completion. Every line ends LF. No protocol CANCEL record; future client uses existing process termination semantics.

Header records:

- `ANALYZE`, sequence 0: payload is existing AnalyzeRequestPayload plus required `analysisStateContext` and `baselineState:null`.
- `REFRESH`, sequence 0: payload is existing RefreshRequestPayload plus required `analysisStateContext`, `baselineState:NativeAnalysisStateHeaderV1` and `targetSourceFiles:SourceFile[]` (complete intended analyzer scope, not only latest reconciliation delta).

`analysisStateContext` is exactly `{providerId, providerVersion, language, resolverVersion, normalizerVersion, policyFingerprint}` using the above header scalars. Worker count is excluded; it remains the private process argument derived from validated indexing configuration. policyFingerprint binds semantic source policy/scope and configuration, not root-path locator or worker count. Computing it belongs to the composition packet; arbitrary mismatched caller values never prove compatibility.

After REFRESH header, emit zero or more `BASELINE_SUMMARY` records with NativeFileAnalysisSummaryV1 payloads. They constitute exactly the baseline bundle; they are not target/upsert records. ANALYZE permits none. A final `REQUEST_COMPLETED` record has exactly `{summaryRecords: nonnegative safe integer, integrityChecksum:64 lowercase hex}`. Hash exact raw bytes of all preceding request records including LF. Even zero-summary ANALYZE requires this completion record. EOF before completion is invalid; never begin source parsing from a prefix. A no-file REFRESH is valid only with a matching empty baseline and target inventory.

REFRESH baseline header context matches base revision ID/fingerprint and analysisStateContext; baseline capabilities match requestedCapabilities as a set. Target files belong to request repository/target revision, unique IDs/paths, and added/modified records equal their target inventory entries. Deleted IDs/paths are absent from target and match baseline prior fingerprint. Unchanged entries match baseline file metadata. Derive the delta with the exact current `detectWorktreeChanges` comparison: contentFingerprint, languageHint, classification.role/provenance/contentKind and sensitivity; same-path identity must be unchanged. Rename is delete plus add. A valid REFRESH requires this complete baseline→target delta to equal submitted changes, independent of array order; detect failed-Apply/empty-latest-delta mismatch rather than claim CURRENT. Different IDs or immutable revisions remain an Application FULL_ANALYSIS_REQUIRED applicability failure; do not silently relabel baseline summaries.

Keep ceilings exactly: aggregate stdin 1,000,000 bytes including all LFs; each line 1,000,000 bytes; stdout 10,000,000 bytes; output events 10,000; stderr 1,000,000 bytes. The request record count is bounded by aggregate bytes and unique source-file inventory, not a new arbitrary cap. Stage summaries in bounded memory for this ≤1 MB input; charge decoded allocations to request maxMemoryBytes before constructing the resolver. Later producer/client packets own cancellation and scheduling; byte validators never imply those are implemented.

Decoder error mapping: byte ceiling → RESOURCE_LIMIT_EXCEEDED; invalid framing/UTF-8/JSON, request ID/sequence drift, missing/extra completion or checksum mismatch → PROTOCOL_CORRUPTION; unsupported protocol value → INCOMPATIBLE_PROTOCOL_VERSION; unknown fields/types, invalid scalar/ownership/context/count/digest/inventory/delta or Java/capability mismatch → INVALID_REQUEST. Validation order is byte/framing → UTF-8/JSON → protocol → envelope identity/sequence/order → payload/bundle/delta → completion/counts → raw integrity. Error messages are fixed bounded diagnostics. This decoder cannot prove a database's active fingerprint; the later Store validates it under transaction.

## APIs and files

Create `packages/providers/src/native-analysis-state.ts`: exported strict `NativeFileAnalysisSummaryV1Schema`, `NativeAnalysisStateHeaderV1Schema`, `NativeAnalysisStateBundleV1Schema`, inferred types, `computeNativeSummaryDigest(summaries): string`, `computeNativeFactContentDigest(fact: ProviderNode|ProviderEdge): string`. Keep canonical JSON helper private.

Create `packages/providers/src/native-ipc-v3.ts`: strict `NativeRequestHeaderV3Schema`, `NativeRequestRecordV3Schema`, inferred types, `validateNativeRequestRecordsV3(records): NativeRequestHeaderV3`. It performs object/context/set validation but not raw integrity. Create `native-ipc-v3-bytes.ts`: `decodeNativeRequestV3(bytes: Uint8Array): {header: NativeRequestHeaderV3; baseline: NativeAnalysisStateBundleV1|null}`. No partial return; controlled `NativeV3ContractError` with code `INVALID_REQUEST|PROTOCOL_CORRUPTION|RESOURCE_LIMIT_EXCEEDED|INCOMPATIBLE_PROTOCOL_VERSION` and safe fixed message, never raw source/records. No DB/spawn side effects. Export from providers index.

Create Rust `analysis_state.rs` and `request_v3.rs`, export through `lib.rs` only. `validate_analysis_state(&Value) -> Result<(), V3ContractError>` and `decode_request_v3(&[u8]) -> Result<ValidatedRequestV3, V3ContractError>` mirror TS semantics; ValidatedRequestV3 contains validated header Value and optional baseline Value. Keep constructors private so callers cannot manufacture validated input. Neither module changes serve_once dispatch. Keep detailed typed language adapters for producer work, not speculative general plugin dispatch here.
