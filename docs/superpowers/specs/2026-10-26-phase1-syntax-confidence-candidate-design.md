# SC-02 Syntax 证据支持度：完整数值候选提案

## 1. 推荐结论与不可省略的局限

建议首版只设置**一个有条件的准入后支持档，score=0.5**；其余输入拒绝输出Confidence。该值的唯一含义是“满足本策略有限适用域内的声明式Source、Syntax字段和必需支持引用契约”，并以明确method/reasons解释剩余不确定性。它不是50%正确率、半数证据通过、执行成功率、质量门槛或发布资格。

**0.5是规范性的数轴中点选择，不是从现有数据估计出的最佳值。现有证据不能证明0.5优于其他内点值。** 选择中点是为了在既有数值形状中固定一个易辨识、无分级排序的契约坐标，避免无依据地精分不同Syntax/解析状态，也避免把0或1当成失败/成功默认值。它不会产生同策略输入之间的置信排名，不自动形成与Code或其他method的可靠性排名，也不新增跨策略聚合算法；已有契约要求的最弱支持上界继续有效。

这意味着首版只是有限的单档支持度规则，不是细粒度量表。若用户需要“哪条更可靠”的多档排序，本方案不能满足，需要新的可比较支持主张、独立依据和单独数值提案。不能批准单档后暗中增加分档或为UNKNOWN/owner-null补惩罚。

0.5不是缺策略/校验失败时的占位值：只有以下全部适用与硬门禁满足、策略已被明确接受且相应Fixture/Evaluation通过，才能由固定代码产生它。缺策略、超预算、不安全、缺Source/ref、版本不适配、输入不可表达或观察不完整，都不产生0.5、0或其他Confidence；现有拒绝保持。

本轮6583项前置摘要匹配；未重跑SC-01的32项或其他产品套件。本文引用的[独立声明语料](../../../fixtures/phase1/syntax-mapping-preparation/README.md)、[证据对应表](2026-10-26-phase1-syntax-support-confidence-crosswalk.json)和历史18例，说明字段/支持关系及局限，不能证明某个数值是测量结果。
