## Scope and alternatives

Choose bounded deterministic scanning of retained summaries. For this first producer, conservatively re-resolve **all requested relation sites in the target summaries**, including unchanged files. This is a complete affected-site superset, not all-source parsing. Emit only actual semantic differences. It avoids an unsound old-resolved-edge reverse index that misses newly resolvable or ambiguous candidates.

Rejected alternatives: a persistent dependency index adds migration/version/invalidation work before measured need; reparsing all sources violates the accepted incremental boundary. A selective site dependency index may be considered later only with Evaluation evidence and review. No adaptive scheduler, new language/framework, public configuration knob, AST persistence, Wiki/Knowledge/Agent feature or new migration belongs here.

Packet C does not modify Canonical IR, ProviderSnapshot v1, strict v1/v2 wire shapes, the public Provider SPI or SQLite activation. Summary/header schema v1 and compatibility discriminators remain unchanged. If a Fixture proves a retained input insufficient, stop and submit an evidence-backed versioned design amendment instead of fabricating it or parsing unchanged sources as a hidden fallback.

## Producer algorithm

1. Use the existing v3 byte/request validators before starting work. Reject duplicate/missing summaries, incompatible context, inconsistent inventory/delta, invalid paths, negative-zero/non-scalar data and oversized framing. A baseline is supplied only by a validated application read in future packet D; digest validity is integrity, not permission or proof of SQLite applicability.
2. Support the accepted same mutable WORKTREE revision ID only. Different IDs or immutable targets are unavailable to this producer. Preserve the closed Native wire error enum: use `INVALID_REQUEST` for this invalid producer invocation, while packet D must expose existing application `FULL_ANALYSIS_REQUIRED` before spawn. Do not add that application code to old wire schemas.
3. Decode retained symbols/sites into existing language structs with checked integer conversion. Reconstruct a baseline index and deterministically regenerate baseline Provider fact digests from summaries. Require exact agreement with both each file's recorded identity/digest/ownership and the deduplicated union before diffing; checking only the union could hide a forged file owner. Reject semantic ledger mismatch as `INVALID_REQUEST`, never guess old state. Reuse the canonical digest recipe omitting only `providerSnapshotId`; this is not a new digest version.
4. Drop deleted file summaries. Parse only added/modified eligible files through existing verified source access, policy, fingerprint, timeout and worker admission. For metadata-only source changes the first implementation may still parse that declared changed file. No unchanged source enters the parser; the explicit resolver-dependent reparse set is empty for this packet. Scanner fingerprint reads are distinct from parser invocations.
5. Retain changed extraction under an explicit byte budget for reuse, rather than implicitly inheriting full-analysis's second source pass. Build a target `DeclarationIndex` from changed extraction plus retained target symbols, imports and inheritance. Keep baseline/target indexes sequential where possible; charge any overlap and decoded summaries against the same request memory budget.
6. Re-resolve every requested target relation site against the complete target index, including old UNRESOLVED/AMBIGUOUS sites. Reconstruct unchanged Provider payloads from summary data using the same full-analysis recipes. Recompute resolution buckets from zero, retaining extraction eligible/covered/unsupported/partial counts and categorical syntax limitations; do not add old resolution counts to new counts. Preserve syntax diagnostics and regenerate target context, not invented evidence.
7. Generate target summary v1 for **every** target file, including unchanged and valid zero-fact files. Its source metadata must exactly match `targetSourceFiles`. The emitted-fact ledger describes the complete target facts, not just patch events. Deduplicate shared identities at graph level, while retaining every file ownership claim in summaries.
8. Diff unioned baseline and target ledgers by `(factType, providerFactId)`: absent target emits removal, new target emits upsert, same identity/different digest emits one upsert, equal digest emits neither. Never emit removal and upsert for one identity. Changed payloads use the new snapshot ID. Shared package containers survive while any target owner remains; owner transfer alone does not replace an unchanged node. Changing an unchanged caller's resolved/ambiguous/unresolved edge is an edge upsert, not a fake source modification.
9. Emit a deterministic stream and successful terminal only when all work fits the existing budgets. Failure, cancellation or a write error produces no applicable candidate. Packet C's successful terminal remains an observation; SQLite applicability belongs to D.

Fact generation must stay bit-for-bit semantically aligned with full ANALYZE. Extract only the shared payload/digest helpers needed by these two paths; do not redesign the whole analyzer. Existing v1/v2/full-v3 regression Fixtures protect this reuse. No source-derived record is a framework interpretation.

## Proposed v3 patch output contract

These are new packet C contracts, not existing exports. Add an isolated strict v3 refresh event schema/byte validator, keeping the full-only union and legacy client unchanged. Reuse versioned Provider node/edge/ref/diagnostic payload schemas and existing stream-context conventions.

| Event                              | Payload and obligation                                                                                                                                                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REFRESH_STARTED`                  | Existing target snapshot/repository/revision/fingerprint context; first, sequence zero.                                                                                                                    |
| `SOURCE_FILE`                      | Existing SourceFile, exactly one for each added/modified request file and none for retained/deleted files.                                                                                                 |
| `UPSERT_NODE`, `UPSERT_EDGE`       | Strict Provider facts in target context; one operation per identity.                                                                                                                                       |
| `REMOVE_NODE`, `REMOVE_EDGE`       | Existing typed Native Provider references, justified by baseline-to-target ledger difference.                                                                                                              |
| `COVERAGE`                         | Existing v2 categorical-plus-statistics payload; exactly one per target file/requested capability, including retained files. Coverage counts are emitted metadata counts, not changed-file or fact counts. |
| `DIAGNOSTIC`                       | Existing bounded diagnostics for the complete target observation; source ranges belong to target inventory.                                                                                                |
| `ANALYSIS_SUMMARY`                 | Existing summary v1, exactly one per target inventory file; no synthetic summary for deleted files.                                                                                                        |
| `REFRESH_COMPLETED`                | Existing refresh context/outcome/count fields plus required `analysisState` header v1 and separate `summaryRecords`. Header matches target fingerprint/context/inventory/digest.                           |
| `REFRESH_FAILED`, `REQUEST_FAILED` | Existing closed failure payloads; started failure vs pre-start refusal respectively.                                                                                                                       |

Terminal counts retain keys `sourceFiles`, `upsertedNodes`, `removedNodes`, `upsertedEdges`, `removedEdges`, `coverage`, `diagnostics`; `summaryRecords` is separate and not a Canonical count. SHA-256 covers exact pre-terminal JSONL bytes, including metadata and LF, as in full v3. No unknown keys or mixed-version/full-only graph events are accepted.

The output validator checks envelope/framing/sequence/context, exact source delta, target summary inventory and digest, coverage cardinality/equations, unique operations, and patch-to-ledger correspondence against validated baseline summaries. Applying operations to the baseline ledger must yield exactly the complete target ledger, with equal digests for unchanged identities and compatible shared ownership. This verifier does **not** replace D's database-bound seal, source recheck, normalization or transaction.

Canonical ordering: target path order using the existing Unicode scalar ordering, fact identity ordering by type/ID within operation categories, capability ordering within a file, and canonical diagnostic/site ordering as in summary v1. Worker completion order cannot select truth or change output semantics. Dependency upserts may reference retained target nodes absent from this stream; validate against the full target summary union, not only upserted nodes.

Outcomes remain `SUCCEEDED`/`PARTIAL` observations. Syntax errors may yield PARTIAL with honest diagnostics; valid empty input yields SUCCEEDED with zero facts. No PARTIAL observation is authorized for canonical activation. Missing language/capability, parser failure, budget failure and resource exhaustion retain their existing distinct closed errors. Do not add raw source, AST or telemetry fields to strict wire records.

## Bounds, process boundary and publication

Preserve aggregate stdin and each line 1,000,000 bytes, stdout 10,000,000 bytes, events 10,000 and stderr 1,000,000 bytes; callers may lower, never raise. Complete target summary output consumes these budgets, even for a one-file change. This design makes no large-repository capacity claim.

Charge input bytes/decoded summaries, both index lifetimes, changed extraction, ledger maps, payload serialization, ordering keys and simultaneous canonical/wire buffers. Use checked/saturating accounting and admission before allocation; bounded worker batches and pending results reuse current scheduling. Synchronous Rust writes provide output backpressure; future D transport awaits sink delivery. Cancellation/deadline checks cover summary reconstruction, resolution and output, not parsing alone. Overflow is `RESOURCE_LIMIT_EXCEEDED`, not omitted dependents or automatic full reparse.

Packet C tests may drive the real binary with bounded test transport and the strict validator. This is not production Runtime transport admission. Packet D must separately specify refresh preflight/streaming, perform paired real-path calibration for its changed exact Node build, obtain explicit numeric approval and prove fresh read/seal/transport memory gates. Current full-bootstrap reservation `280,453,120 + 2 × retained SQL UTF-8 bytes` is **not** refresh admission evidence. Do not overwrite historical profiles or transplant synthetic memory evidence.

Accepted C1 boundary supplements this Rust accounting paragraph: Node wire/work charging is not RSS accounting. Private Runtime guards the out-of-band positive safe budget before a synchronous lazy opener; Provider owns at most1,000,000-byte input snapshot and checks exact embedded-budget equality before output. Separate REFRESH_VERIFY static evidence measures all Node copies/maps/ordering/concurrent buffers with startup-inclusive peaks, independent holdout and required actual-port checks. It owns no SQL and borrows no full/read profile. Full-only compatibility is separately recalibrated on the same final build. Exact signatures/fields/order/errors are normative in the accepted amendment; revised-plan and numeric approvals remain real holds.

Keep DESCRIBE incremental capability unadvertised until real composition and task Evaluation pass. Existing protocol list `[1,2,3]`, IR `[1]` and evaluated Java capabilities remain unchanged by C. A producer test alone cannot make general Provider routing select incremental support.
