# Phase 0.5 Design Amendment and Compatibility Report

Date: 2026-09-24. Review base: `393b3c296ad18e3271886533925255c5dc488f7f` on `codex/p05-w2-001-repository-discovery`. Scope: backward-compatible design and code audit; no product implementation, Fixture baseline, migration, or quality threshold changed in this amendment.

## Decision and unchanged architecture

This increment reuses accepted ADR-013 (published-Knowledge-only Wiki projection) and ADR-014 (language-neutral NativeProvider and bounded Java-first analysis). No new ADR is required because the user confirmed that System Wiki's engineering content must be grounded through published Knowledge; raw current engineering facts can instead feed separate read-only Diagram or Agent Context views. If a future implementation needs Wiki to read raw facts directly, stop and propose an ADR amending ADR-013 before changing that boundary.

The TypeScript control plane, Rust/Tree-sitter analyzer, versioned JSONL IPC, provider-independent Canonical IR, TypeScript-owned SQLite activation, `ExecutionGraph -> RuntimeFlow -> BusinessFlow`, Evidence/Claim/Candidate/Published Knowledge separation, AUTO engineering facts, MANUAL semantic publication, local-first/remote opt-in, and last-good-state recovery remain unchanged. Phase 0 is not reopened. The Phase 0.5 original exit gates and numeric thresholds remain in force; the added Worker Consistency and outcome checks constrain existing tasks rather than replacing those gates.

## Milestone and follow-up

No milestone is renumbered and Phase 0 is not reopened. P05-W2-001 remains the first implementation task after its written design and implementation plan are reviewed. Worker/resource/outcome additions map to existing Phase 0.5 task IDs. Phase 1 remains DESIGN-READY; bounded candidate degradation, System Wiki, and Agent context are refined into reviewed tasks only after Phase 0.5 acceptance. Phase 2 remains ARCHITECTURE-READY; its design direction expands to complete degradation orchestration and DiagramModel/renderer alongside declarative WikiSpec, but concrete schedule and gates require Phase 2 planning evidence rather than an immediate promotion requirement. Deferred Phase 3 capabilities remain deferred. No new numeric Quality Gate or Phase 4 is introduced.
